**Goal:** A playable, accessible neon Snake on phones and tablets:
- Compose menus, splash and HUD
- a libGDX board embedded in Compose
- swipe, D-pad and key controls; synthesized sound; haptics; TalkBack
- UI tests on three emulator profiles in CI, the 16 KB check, and hardened backup rules

Every new decision lands in `:domain` under the 100% gate.

**Architecture:**
- `:domain` (exists) gains the decisions the app needs, in the same flat package, each under the 100% gate:
  - screens and the back stack
  - overlays and spoken lines
  - sound and haptic feedback, and the tone synthesizer
  - the board scene, the particle burst, the palette and contrast maths
- `:board` (new, Kotlin JVM, package `io.github.eastwoodno1.supersnake.board`) holds one libGDX `ApplicationListener` that draws a `BoardScene` and does nothing else.
- `:app` (exists) holds:
  - the composition root, the `Clock` and `RandomSource` adapters
  - ViewModels with no branching, the Compose screens
  - the libGDX fragment, hosted with `AndroidFragment`
  - the audio, haptic and TalkBack sinks
- Graph: `:app → :board → :domain`, `:app → :data → :domain` (main spec §5).

**Tech Stack:** Kotlin 2.4.20, AGP 9.5.0, Compose BOM 2026.09.00, fragment-compose 1.9.1, lifecycle 2.11.0, core-splashscreen 1.2.0, libGDX 1.14.2, DataStore core 1.3.0. Instrumented tests use Compose UI test, AndroidX Test and JUnit 4.13.2. CI uses ReactiveCircus/android-emulator-runner v2.38.0.

## Review Focus

1. **Rotation or backgrounding mid-game, including during the countdown.**
   - The game pauses, and the snake, orb and score survive.
   - The board redraws after the GL surface is recreated, and resume runs the countdown from 3 (C20).
   - Pinned in Task 4 (`rotationPausesAndKeepsTheGame`, `backgroundPausesTheGame`).
2. **Two frame loops after a rotation.** A second `advance()` loop would double the speed. Expected: one loop per visible game screen, so steps keep the difficulty's interval. Pinned in Task 4 (`oneLoopAfterRecreate`).
3. **A double tap on Play, Restart or Play again.** Expected: one game and one `GAME` entry on the back stack. Pinned in Task 1 (`pushingTheTopAgainChangesNothing`) and Task 6 (`doubleTapPlayStartsOneGame`).
4. **200% font scale on a phone in landscape.**
   - Menu, settings, high scores and overlays scroll instead of clipping.
   - Every button stays at least 48 dp.
   - Pinned in Task 8 (`fontScale200NothingClips`).
5. **Settings changed mid-game or between games.**
   - Sound and haptics off take effect on the next frame.
   - A difficulty change applies from the next game, never the running one (C18).
   - Pinned in Task 2 (`soundOffSilencesEverything`) and Task 7 (`difficultyChangeWaitsForNextGame`).

### Task 1: Screens, overlays, spoken lines and swipe control

**Branch:** `feat/app-decisions` · **PR title:** `feat: add back stack, overlays, spoken lines and swipe control`

**Files:**
- Create in `domain/src/main/kotlin/io/github/eastwoodno1/supersnake/domain/`: `BackStack.kt`, `Overlay.kt`, `Spoken.kt`, `SwipeControl.kt`
- Create in `domain/src/test/kotlin/io/github/eastwoodno1/supersnake/domain/`: `BackStackTest.kt`, `OverlayTest.kt`, `SpokenTest.kt`, `SwipeControlTest.kt`

**Interfaces:**
- Consumes (Plan 2):
  - `GameFrame`, `GameStatus`, `Announcement`, `GameInput`
  - `SwipeTracker`, `SwipeStep`, `Direction`
- Produces:
  - `enum class Screen { MENU, GAME, HIGH_SCORES, SETTINGS }`
  - `data class BackStack(val screens: List<Screen> = listOf(Screen.MENU))`, with:
    - `val top: Screen`
    - `val canPop: Boolean`
    - `fun push(screen: Screen): BackStack`
    - `fun pop(): BackStack`
    - `fun home(): BackStack`
  - `enum class Overlay { NONE, COUNTDOWN, PAUSED, GAME_OVER, WON }`, with `companion object { fun of(frame: GameFrame): Overlay }`
  - `enum class BackAction { PAUSE, LEAVE }` and `object GameBack { fun action(status: GameStatus): BackAction }`
  - `enum class Phrase { COUNTDOWN, GO, PAUSED, ORB_MILESTONE, GAME_OVER, WON, NEW_HIGH_SCORE }`
  - `data class Line(val phrase: Phrase, val value: Int?)`
  - `data class Spoken(val lines: List<Line>, val sequence: Long)`, with `companion object { fun next(previous: Spoken?, announcements: List<Announcement>): Spoken? }`
  - `class SwipeControl(private val thresholdPx: Float)`, with:
    - `fun down(pointerId: Int, x: Float, y: Float)`
    - `fun move(pointerId: Int, x: Float, y: Float): List<GameInput>`
    - `fun up(pointerId: Int)`

Rules:
- **Back stack.**
  - `push` of the screen already on top returns the same stack (Review Focus 3).
  - `push(MENU)` is `home()`.
  - `pop` at the root returns the same stack, and `canPop` is `false` there, so `:app` lets the system finish the activity.
- **Overlay:**

  | Frame | Overlay |
  |-------|---------|
  | `COUNTDOWN` | `COUNTDOWN` |
  | `RUNNING` | `NONE` |
  | `PAUSED` | `PAUSED` |

**[builder] B8, the beeps:**
- Notes:

  | Sound | Notes |
  |-------|-------|
  | `COUNT` | 440 Hz × 80 ms |
  | `GO` | 880 Hz × 150 ms |
  | `EAT` | 1320 Hz × 40 ms |
  | `CRASH` | 220 Hz × 120 ms, then 110 Hz × 240 ms |
  | `WIN` | 523, 659, 784, 1047 Hz × 100 ms each |

- Square wave at amplitude `8192` (a quarter of full scale).
- 5 ms linear attack and release per note, so notes don't click.
- Sample `i` of a note is `+A` when `(2 × i × f / sampleRate) % 2 == 0` in integer maths, else `−A`, times the envelope.
- Length is `Σ durationMillis × sampleRate / 1000`.
- `sampleRate ≤ 0` gives an empty array.

**[builder] B9, the mapping** (all from the frame alone):

| From the frame | Sound | Haptic |
|----------------|-------|--------|
| `Countdown(n)` | `COUNT` | none |
| `Go` | `GO` | none |
| `ORB_EATEN` | `EAT` | `TICK` |
| `LOST` | `CRASH` | `REJECT` |
| `WON` | `WIN` | `CONFIRM` |

- Sounds come first in frame order.
- `soundOn = false` empties `sounds`, and `hapticsOn = false` empties `haptics`.
- Nothing plays for `Paused`, milestones or a new high score: those are spoken, and pause has its own overlay.
- `:app` maps `TICK`, `REJECT` and `CONFIRM` to `HapticFeedbackConstants.CLOCK_TICK`, `REJECT` and `CONFIRM` through `View.performHapticFeedback`. That needs no `VIBRATE` permission and follows the system haptics setting.
