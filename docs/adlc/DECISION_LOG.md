## Decision Detail

### DEC-007 to DEC-008 - Merge method: rebase, then squash

Original decision (S1, AI call): rebase merge only. New evidence (S2, PR #6): the repo allowed only rebase, which sat badly with the owner's wish for one commit per PR. Reconsideration: the owner said "I want squash merges". Revised decision: squash only, with the PR title as the Conventional Commit header (hence the 64 character limit and the PR title check). Consequences: ADR-0007 was rewritten in place (its context records the original), and a PR (#8) had to change the settings script, the live settings, the ruleset, the spec and the plan together, because a partial update would have left PRs unmergeable. Educational significance: reversing a spec decision is cheap only when you know every place it lives.

### DEC-021 to DEC-022 - Dependabot reminder, then split

Original: keep failing PR #28 open as a visible reminder that Kotlin is capped. New evidence: Kotlin bumps were bundled with other Gradle updates, so one cap failure blocked unrelated updates (Reconstructed from PR titles #28 "gradle group", #41 "kotlin group"). Revised: separate Kotlin group in PR #40. Consequence: #28 was closed unmerged and Kotlin PR #41 now carries the reminder. The reasoning was not captured.

### DEC-026 - Redaction too clever

Original (first draft of the plugin): treat any `LETTERS-123` token as an internal issue key. Problem: it destroyed ADR-0006, SHA-256, UTF-8 and similar. Revised: an owner-listed key set, with the model-side filter and `scan.sh` as the other layers. Trade-off: an unlisted internal key now relies on the model filter and the pre-commit scan.
