# Concepts and principles learned

- A symptom (the goldfish abort) can come from CI environment setup (AVD ini), not from the tool versions.
- The test-image variant (`google_atd` vs `google_apis`) decides which UI tests can run at all.
- Software-rendered large-screen emulators need condition waits.
- A stale number in a task ("6/6") needs checking against reality.
- A guard script against false greens (0 tests run) proved useful.

# Durable lessons

- When a run is red in CI, read the artifacts and the per-test timing before changing timeouts, because the tablet shade needed 8.7 s and the guessed 5 s was wrong.
- Print the evidence for a claim (for example PATH) in the run that tests it, because the PR body overclaimed otherwise.
- Use a child issue to keep the parent open when `pr-rules` demands `Closes`.
- A lint gate failing on a new AGP release blocks every push, so bump in a separate PR and do not use `--no-verify`.
